# Aura 代码规范

本规范自包含，禁止依赖项目外的规范或指引，不链接、调用或要求加载其他 skill。支持文件只放在本 skill 目录内，内部文件可以互相引用。项目源码、工具配置及记录是事实输入，不是外置规则。

## 按代码范围读取

- 宿主 `apps/*`、`packages/*`、根脚本和测试：读取 [TypeScript 与 React](references/typescript-react.md)。
- 插件原生 ESM JavaScript：读取 [插件 JavaScript](references/plugin-javascript.md)。插件后端或页面 TypeScript 同时采用适用的 TypeScript 规则及该插件配置。
- 保留目标目录已有的明确例外；产品 `site-launcher` 使用双引号与根锁文件，不把新插件默认值强行应用于旧代码。

## 共同边界

- 仅格式化本次修改范围；格式和行为变更分别审查，不因规范整理改名公共字段、注册 ID、提示词、正则或嵌入源码。
- 异步工作明确等待和失败处理，传播取消；输入先校验，资源由明确所有者释放。
- 凭据只留在 backend，不进入响应、日志或上下文；用户配置写入保留 revision 检查，未知付费结果不自动重发。
- 格式由实际 Prettier 配置决定，Lint 由目标配置执行。不扩大历史基线或关闭规则掩盖问题，未运行的检查不能记为通过。

## 多语言文案与错误

- 新增或修改用户可见文案时，同步提供 `zh-CN`、`en`、`ja`、`ko`、`ru`、`fr` 六语。范围包括宿主、原生提示、产品插件、表单校验、异步状态和错误；英文回退用于兼容缺项，不代替产品六语的完整交付。
- 宿主复用 `@aura/i18n` 的 i18next + react-i18next 运行时与现有领域消息模块；插件通过公开 `@aura/plugin-ui` 使用宿主语言。文案采用稳定语义键、完整句子与插值，不硬编码某一种语言、不拼接翻译片段；数量使用语言对应的复数形式，日期、数字和单位使用现有 `Intl` 格式化能力。
- 需要保留的通知、校验与异步错误保存语义键或 `MessageReference`，在渲染时翻译；本地错误使用 `MessageError`、`errorMessage` 和 `messageText` 保留引用。不把译文用作条件、ID、枚举值或持久化状态，不从历史句子猜测错误类型。
- 后端在拥有错误上下文的分支提供稳定 code 与经过协议校验的有界 params，保留原 message/status 和未知错误回退。参数只投影公开 ID、受控枚举或数值等声明过的安全字段，不携带凭据、私有路径、签名 URL、完整输入、原始上游响应或 cause；backend/shared 不导入前端翻译运行时。
- 插件拥有业务词库、静态名称/说明和 Schema 显示标签，通过公开 SDK 声明。插件后端可使用 `ActionFailure` 的译文选项或 `PluginFailure` 提供受限的公开说明；宿主负责校验与显示，不集中硬编码各插件的业务文案。显示详情不进入 Flow/Action 输入输出、模型上下文、执行身份或持久化记录。
- 用户输入、自定义名称、模型 ID、路径、命令、源码、日志、AI 输出和没有翻译声明的第三方文本保留原值。界面语言与 AI 回复语言独立；切换语言不得改写历史、业务配置或提示词，不得重新请求业务数据、保存、重试或发起付费请求。
