# Aura UI 开发规范

适用于宿主页面、共享组件、插件工作台页面与 Run 结果视图。浏览器、Electron renderer 和 Capacitor WebView 共用 React DOM 与 CSS 实现。

本规范自包含，不依赖项目外规范，不链接、调用或要求加载其他 skill。项目源码与工具配置是事实输入。以下规则用于新增和修改范围；保留既有组件的明确例外，不借样式调整批量改造无关页面。

## 1. 设计方向与实现入口

Aura 是紧凑的创作工作台：中性底色、清晰文字层级、克制的主题色反馈。通过分隔线、工具栏、内容分组和独立滚动区建立层级，减少重复边框、卡片套叠与装饰占位。

默认深色「夜航」、浅色「晨雾」使用紫色品牌色；用户选择自定义主题色、字体或圆角后，页面与插件必须跟随当前外观，不能重新固定成默认紫色。

开发前按改动范围核对这些实现：

| 内容                                   | 仓库内事实来源                                                                    |
| -------------------------------------- | --------------------------------------------------------------------------------- |
| 色板、字体、字号、间距、圆角与基础动效 | `packages/frontend/ui/src/theme.ts`                                               |
| 共享基础组件与主题上下文               | `packages/frontend/ui/src/components.tsx`                                         |
| 图标样式与工具类                       | `packages/frontend/ui/src/icons.css`                                              |
| 外观派生与变量注入                     | `packages/frontend/workbench/src/appearance.ts`、`useAppearance.ts`               |
| 全局交互状态与工作台布局               | `packages/frontend/workbench/src/styles.css`、`workspace-chrome.css`、`shell.css` |

先复用现有组件、变量与相邻布局模式，再补充缺失能力。发现文档与实现不一致时明确指出差异，不把偶然的局部写法扩散为全局规则。

## 2. 主题与配色

### 消费方式

- 宿主 React 组件通过 `useTheme()` 消费当前 `colors`、`dark`、`reduced`；CSS 使用宿主注入的语义变量。
- `palettes.dark/light` 是默认色板，不是页面自行选择主题的入口。页面不得绕过当前外观直接固定使用默认色板。
- 新增颜色先寻找已有语义 token；确需新增时，在共享主题层定义并补齐深浅主题，不在页面建立第二套色板。
- 页面不硬编码品牌色、正文色、背景色或状态色。渐变、透明色和阴影从现有 token 派生；媒体内容、品牌原图、语法高亮及图表专属色另按其语义处理。
- 弹窗、Popover、Portal 和插件视图必须获得当前主题、字体与圆角；挂载到根节点外时核对变量继承和共享样式作用域。

### 语义映射

| 用途                                 | CSS 变量                                                          |
| ------------------------------------ | ----------------------------------------------------------------- |
| 页面、侧栏、内容表面、浮层、输入背景 | `--background`、`--sidebar`、`--surface`、`--elevated`、`--input` |
| 普通边框、弱分隔线                   | `--border`、`--hairline`                                          |
| 正文、次级说明、辅助文字、弱元信息   | `--text`、`--secondary`、`--muted`、`--caption`                   |
| 链接、强调与当前状态                 | `--accent`                                                        |
| 主要操作底色与前景                   | `--primary`、`--primaryText`                                      |
| 柔和高亮、按下状态                   | `--soft`、`--pressed`                                             |
| 成功、危险或错误、警告               | `--success`、`--danger`、`--warning`                              |
| 用户消息、主题光晕                   | `--user`、`--glow`                                                |
| 悬浮提示背景与文字                   | `--tooltip`、`--tooltipText`                                      |

默认品牌值：深色 `primary #8052EA / accent #BDA1FF`，浅色 `primary #6D40CD / accent #6942B4`；`primaryText` 为白色。这些数值只由主题层持有，消费方使用 token。

- 主要操作使用 `primary/primaryText`；普通操作使用中性背景和文字，避免一个区域内所有按钮都呈主操作样式。
- 成功、错误和警告保持语义颜色，不随品牌色替换；同时提供文字或图标，不能仅靠颜色传达状态。
- `caption` 只用于弱元信息，不用于关键操作、表单标签或错误说明。检查实际背景上的可读性，不能因使用了 token 就假定对比度足够。
- 占位文字使用 `--muted` 且 `opacity: 1`；禁用透明度由外层控件承担，避免文字与图标重复衰减。

### 交互效果

统一复用以下变量，不逐页重画渐变与光圈：

- 输入聚焦：`--focus-border`、`--focus-wash`、`--focus-shadow`。
- 菜单、导航和行高亮：`--highlight-fill`、`--highlight-sheen`。
- 主操作默认、悬停、按下：`--control-fill`、`--control-hover-fill`、`--control-pressed-fill`。
- 普通按下反馈：`--pressed-fill`。

复合搜索框、路径输入和输入卡片由外层承接焦点，内部输入不再叠加边框与光圈。危险操作使用危险色反馈；禁用项不显示悬停、按下或焦点装饰。

宿主组合行使用 `data-row-highlight`，从属按钮使用 `row-control`，整行只绘制一层背景和焦点反馈。插件采用同样的视觉原则；使用宿主 class 前核对其实际作用域。

## 3. 字体与排版

- 界面继承 `var(--font-text)`；代码、终端与需要等宽对齐的内容使用 `var(--font-mono)`。
- 默认界面字体来自系统栈，包含 Apple 系统字体、Segoe UI、PingFang SC、Microsoft YaHei；默认等宽栈包含 SF Mono、JetBrains Mono、Fira Code、Consolas。
- 尊重外观设置中的 system、serif、mono 字体选择，不在局部页面重设系统字体；代码区仍使用独立等宽栈。
- 默认不下载、打包或远程加载字体；确有字体资源需求时作为独立设计变更处理。
- 普通文字、输入值和标签默认 400；强调及一般标题默认 600；中间层级可用 500。优先通过字号、字重和间距建立层级。

| 用途                           | 字号 / 行高 | 字重 |
| ------------------------------ | ----------- | ---- |
| 主视觉标题 `hero`              | 28 / 38px   | 600  |
| 页面标题 `title`               | 20 / 28px   | 500  |
| 正文 `body`                    | 14 / 22px   | 400  |
| 辅助文字 `small`、标签 `label` | 12 / 18px   | 400  |

工作台控件通常使用 12–14px；代码默认 12px。长文可沿用所属阅读组件的行高，不把所有文本强制压为控件行高。避免为每个组件新增字号。

标题、按钮和输入值必须在简体中文、英文、日文、韩文、俄文、法文及用户字体切换后保持可读，不依赖固定字符宽度布局。核对中日韩字形的系统字体回退；截断内容应有查看完整值的方式。

## 4. 间距、圆角与尺寸

- 间距优先使用 `spacing` 刻度：4、8、12、16、24、32px；同一层级保持一致，小间距表达关联，大间距区分分组。
- 共享圆角刻度为 4、8、12、16、20px，面板刻度为 28px。新元素优先采用刻度；既有按钮、菜单和输入卡片保留所属组件的明确尺寸。
- 可配置圆角使用 `calc(<基础值> * var(--radius-scale, 1))`。当前 square/default/rounded 对应 0/1/1.5，页面不得自行解释或覆盖这三个档位。
- 圆形操作按钮、轨道、头像和胶囊等依赖几何形状的元素保留其圆形或胶囊形状，不机械乘圆角系数。
- 共享 `Button` 默认最小高度 40px，compact 为 34px；共享 `IconButton` 为 34px。已有工具栏的紧凑控件按同类组件保持一致。
- 触屏操作目标至少 40×40px；小图标可通过外层 padding 扩大点击区域。仅悬停出现的操作在触屏也必须可达。
- 分隔线优先 0.5px `hairline`，控件边框通常为 1px `border`；沿用相邻组件的实际线宽，避免相邻双边框。

## 5. UI 组件与图标

### 复用与边界

- 宿主优先复用 `@aura/ui/components` 的 `Button`、`IconButton`、`Label`、`Reveal` 等已有能力；包内菜单、提示和弹层沿用现有实现。
- 没有合适封装时使用语义化 HTML 与共享样式；不要为一次使用构建大型组件体系，或另引入整套视觉语言不同的组件库。
- 通用视觉原语归 `@aura/ui`；宿主交互组合归 workbench；插件业务组件保留在插件内。
- 插件只使用当前宿主实际公开并提供的模块，不导入宿主私有源码，不假设所有 `@aura/ui` 导出都已注入插件运行时。
- 插件 CSS 限定在插件根节点或专有 class 内，不覆盖 `body`、全局元素或宿主 class。宿主已加载的共享图标样式不重复注入。

### 状态与可操作性

按组件用途覆盖默认、悬停、按下、键盘聚焦、禁用，以及适用的选中、加载、成功和错误状态。

- 使用原生 button、input、select 等语义；表单字段有可关联的标签，placeholder 不代替标签。
- 纯图标按钮提供 `aria-label`；展开、选中和当前位置使用对应的 ARIA 状态。
- 加载状态保留控件几何，避免文字变更造成布局跳动；重复提交按实际业务状态阻止，失败后提供可理解的恢复方式。
- 菜单支持键盘导航与 Escape；弹窗管理初始焦点和焦点范围，关闭后合理恢复焦点。
- 浮层沿用现有 Portal、dialog 或 Popover 机制，避免靠不断增大 z-index 解决遮挡。位置受视口约束，短窗口内允许内容滚动。
- 键盘聚焦必须可见；forced-colors 模式保留系统轮廓，不能仅依赖渐变或阴影。

### 图标

使用 Lucide 或共享规则下的自有 SVG。宿主已加载 `@aura/ui/icons.css`；独立入口才按需加载公开样式。

| 用途         | class / 约定                            |
| ------------ | --------------------------------------- |
| 普通线性图标 | Lucide 默认或 `aura-icon`，线宽 1.6     |
| 主要操作     | `aura-icon--emphasis`，线宽 1.8         |
| 大号占位     | `aura-icon--display`，线宽 1.25         |
| 实心符号     | `aura-icon--filled`，保留所需 fill      |
| 共享尺寸     | `aura-icon--xs/sm/md/lg`：12/14/16/20px |

自有线性 SVG 使用 24×24 viewBox、`fill="none"`、`stroke="currentColor"`、圆端点与圆连接。悬停和选中不改变描边粗细。

图标默认继承 currentColor；采用 `aura-icon--secondary/muted/text/accent/danger/success/on-primary` 色阶类时，不再传固定 color。装饰图标设 `aria-hidden`。

图表、流程连线、品牌标志和媒体画布保留自身绘制规则；特殊图形可通过 `aura-icon--custom` 保留几何。

## 6. 布局与响应式

- 页面填满宿主提供的可用区域；Flex/Grid 的可收缩子项设置适当的 `min-width: 0`、`min-height: 0`，避免长内容撑破面板。
- 主滚动容器填满所属区域，滚动条贴区域右边缘。居中、max-width 和内容留白放在滚动容器内部，不缩窄整个滚动区域。
- 代码块、宽表格和媒体允许局部横向滚动；普通页面不得因长路径或文本出现整体横向溢出。
- 工具栏、导航和底部输入区保持稳定；滚动主要发生在内容区，避免重复嵌套纵向滚动容器。
- 主区响应式优先依据扣除侧栏后的实际容器宽度。使用 `workspace` 容器查询；窗口栏、抽屉、安全区和输入设备能力使用媒体查询。
- 沿用既有断点：workspace ≤820px 时设置导航横排、相关详情全宽；≤700px 时工作流操作换行；settings-body ≤600px 时主题选项和表单单列。新布局根据内容需要选择断点，不把这些数值套用到所有组件。
- 主体不设统一的 1200px 总宽度上限；阅读区保留内容宽度上限，工具和编辑区域按任务利用剩余空间。
- 插件页面返回可铺满视口的根节点，滚动留在页内；不要按初次窗口尺寸或消息内容冻结宽高。
- 窄屏允许操作区换行、面板切换为抽屉或全宽视图；变宽后自动恢复，不因响应式变化改写用户保存的布局。
- 尊重宿主 safe-area 与桌面拖拽区域；可交互控件不能落入不可点击的窗口拖拽热区。

## 7. 动效与动画

动画用于解释状态和空间变化，不延迟操作、阻挡阅读或制造持续注意力竞争。

| 场景            | 当前参数     | 使用方式                                  |
| --------------- | ------------ | ----------------------------------------- |
| 共享按钮按压    | 100ms        | 使用 `motion.press`；共享按钮缩放至 0.975 |
| 共享内容入场    | 200ms        | 使用 `motion.enter`；透明度与 12px 位移   |
| 工作台菜单入场  | 130ms        | 透明度与 4px 位移                         |
| 侧栏展开 / 收起 | 220ms        | 使用 `--workspace-sidebar-duration`       |
| Orb 装饰轨道    | 24000ms / 周 | 使用 `motion.orbit`，仅用于对应品牌组件   |

- 基础入场曲线为 `cubic-bezier(0.4, 0, 0.2, 1)`；工作台空间切换使用 `--workspace-motion-ease`，当前为 `cubic-bezier(0.22, 0.75, 0.22, 1)`。旋转使用 linear。
- 优先动画化 transform 和 opacity；只声明实际变化的属性，不使用 `transition: all`。需要改变布局的面板沿用现有实现，避免过渡中反复测量并修改布局。
- 侧栏与主区边缘同步移动；右侧面板移动时保持内容宽度，避免终端和文字反复折行。拖拽调整尺寸直接跟随指针。
- 流式文本更新不重播整段入场；不要给每个 token、列表刷新或普通状态更新增加动画。
- 循环动画限于必要的进度反馈与现有品牌组件；焦点光效保持静态，不增加扫光、呼吸或闪烁。
- 同时尊重系统 `prefers-reduced-motion` 与应用 reduceMotion，任一开启即减少动态效果。React 使用当前 reduced，CSS 同时覆盖系统媒体查询和宿主 `data-reduced="true"`；根外弹层也必须生效。
- 减少动态效果时关闭位移、缩放、旋转和装饰循环，保留即时颜色反馈与文字状态；逻辑完成不能依赖 animationend 或 transitionend。
- Hover 效果限定在支持悬停的设备；支持半透明材质的区域在减少透明度模式下恢复实色。
- 动画、计时器和监听器随组件卸载清理，后台或不可见内容不持续运行无意义动画。

## 8. 多语言与显示文案

- 宿主、原生应用提示和随产品发布的插件须完整支持 `zh-CN`、`en`、`ja`、`ko`、`ru`、`fr`。新增/修改页面时同步覆盖标题、导航、按钮、菜单、提示、placeholder、空态、加载、成功/失败、确认与 ARIA 标签，不只翻译正常路径。
- 宿主复用 `@aura/i18n` 和现有领域消息 Hook；插件通过公开 `@aura/plugin-ui` 注册自有词库、使用 `usePluginTranslation`，复用宿主语言运行时。资源本地发布、按 namespace 管理，缺项回退英文；刷新替换旧键，卸载时清理。插件静态名称、说明和 Schema 显示标签通过 manifest 声明，不能以执行停用插件或预先加载页面 bundle 为前提。
- 使用完整句子与插值，数量采用语言对应的 CLDR 复数形式，尤其覆盖俄语的 `one`、`few`、`many`、`other`；日期、耗时、数字、文件大小和金额使用现有 `Intl` 格式化，保留业务指定的时区、精度、币种和计算阈值。
- 保留的通知、校验和错误使用语义键/消息引用，展示时按当前语言解析。用户内容、自定义名称、ID、路径、命令、日志、源码、模型输出和没有翻译声明的第三方文本保持原文；Schema 只映射显示标签，不改实际枚举值或提交内容。
- 切换语言只更新显示，保留草稿、选择、焦点、展开状态、缩放、运行与连接。不得把 locale 用作组件 key，不因语言变化重建编辑器、订阅或轮询、重新导航、请求业务数据、提交、保存或发起模型请求；本机语言偏好仅随用户显式选择保存。
- 检查法文/俄文长文案、中日韩字形和窄屏换行。按钮、表单、错误提示和浮层须能容纳译文，不靠固定字符宽度、缩小字号或强制显示英文掩盖溢出；继续尊重用户字体与外观设置。
- 原生应用自己的标题、提示和按钮跟随应用语言；系统按钮由操作系统本地化。语言切换不关闭或重开已显示的原生对话框，后续打开时应用新语言；路径、过滤条件和取消语义保持不变。

## 9. 验证与交付

按改动范围核对，不对每次局部调整重复完整矩阵：

- 主题与外观：深色、浅色；涉及 token、字体或圆角时，检查自定义主题色、字体切换和圆角档位，并覆盖根外弹层与受影响插件。
- 布局：宽屏、窄容器、侧栏调整、短窗口、长文本和溢出；缩窄后再放宽，确认布局可恢复。
- 多语言：按受影响范围验证全部六语、俄语复数、法文/俄文长文本、中日韩字体与 320px/360px 窄容器；确认切换语言后草稿、焦点、运行、连接和请求次数保持不变。
- 交互：键盘焦点、触屏可达性，以及相关的禁用、加载、空态、错误和恢复。
- 动效：正常模式、系统减少动态效果、应用减少动态效果；涉及焦点时检查强制颜色模式。
- 运行受影响包的 typecheck；非平凡交互变化补充聚焦行为测试，源码改动执行格式与 Lint 检查。产品插件改动执行 `pnpm run check:product-plugins`。
- 视觉变化检查实际渲染；类型检查不能代替视觉验证。验证截图和临时输出放根 `local/`，只报告实际执行的检查和未覆盖范围。
