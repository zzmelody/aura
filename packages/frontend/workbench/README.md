# @aura/workbench

性能与资源生命周期：设置、记录、自动化及工作流页面按需拆包，工作流编辑器首次访问才挂载。目录使用 ETag 条件请求，正常每 15 秒校验，窗口重新可见时立即校验；未就绪时短间隔重试，后台窗口暂停目录请求。文件 diff 按 hunk 对象弱引用缓存，已完成回合独立 memo，计时只更新运行回合。

对话历史使用 DSH 稳定游标向前分页，界面每次显示最多 40 轮，并提供较早、后续及返回最新操作；最多缓存六段最近访问的对话，当前和正在执行的对话始终保留。旁支首次打开才读取历史，隐藏且无运行任务、无附件 60 秒后释放界面，保留草稿；切换不会停止执行。Run 由 `workflow-run-store.ts` 按 endpoint 与 Run ID 共用读取、取消和轮询，未变化快照保持引用稳定，最多保留 50 个无订阅缓存。

Site 页面及项目列表状态已迁到 `plugins/site-launcher/client/src/`。工作台通过 DSH 页面贡献加载它们，不再硬编码业务页面。`src/screens` 保留通用对话、工作流与设置；工作区、导航兼容映射和宿主适配留在根模块。`@aura/workbench/plugin` / `transport` 提供公开的通用工作流控件、JSON/媒体传输及原生目录/预览适配，插件不导入私有源码。目录职责见 [模块边界](../../../docs/development/module-boundaries.md)。

浏览器、Electron 与 Capacitor 共用的 Aura React Web 工作台，包含界面、导航、交互状态、Web Storage 和 HTTP transport。应用只提供 React DOM 运行时及少量宿主能力；本包只依赖 frontend/shared 库，不读取后端凭据，也不启动 DSH。

移动端入口位于 `apps/mobile`，桌面端入口位于 `apps/desktop`。两端复用同一个 `App` 导出，平台启动、窗口和发布配置留在各自应用中。

`App` 可接收宿主的 `onReady` 回调：本地状态恢复并在 Suspense 中提交首屏后，通知当前外观和减少动态效果设置。桌面入口用它结束独立启动动画；该通知不等待后端或插件服务，Web 和移动端可省略回调。

## 紧凑工作台

输入框的 `/` 与「＋ → 命令、Skills 和 Flows」共用一个菜单，按「内置命令 / Skills / Flows」逐级展开，输入关键词时搜索三类项目。内置命令提供模型选择、停止当前生成和清空输入；Skills 读取当前工作空间的 DSH 用户可调用目录，选中后插入 `/name `，继续填写任务再发送；Flows 打开现有参数表单。菜单与整个输入卡片左对齐，始终在卡片上方留出间距，列表单独滚动。方向键、Enter/Tab、返回按钮和 Esc 均可操作；关闭菜单保留草稿。

主对话与侧边对话共用独立加载的输入卡片样式：24px 圆角、上方输入、下方操作。新旧对话均置底，主、旁支输入卡片底边对齐；空草稿使用相同高度，多行草稿向上增高。「带回主对话」位于旁支输入框上方。左侧「＋」收纳图片和工具入口，工作空间作为同一行的文件夹菜单，可切换或新建，不再挂在卡片下方。右侧显示模型、思考强度与圆形发送按钮；模型菜单内切换 Codex、Lumina、自定义 API 或演示服务。输入框自动增高到 220px 后内部滚动，窄卡片收起思考强度文字并截断长名称。生成中空草稿只显示停止，填写引导后并列显示发送，保留原有引导链路。

输出区按事件时间线交错显示 AI 文字、工具组、问题、用户引导和嵌套工作流，结束与历史回放保留相同顺序。连续工具调用默认合并为折叠摘要，空白文字不拆组；各组独立展开，顶部状态行可统一展开或收起。摘要保留执行中、失败和中断状态，展开后查看单项及文件差异；流式更新和完成不会重置用户选择。折叠不隐藏 AI 文字、问题或引导。授权决定使用输入框上方的独立卡片，输出区仅在决定后留下记录；等待期间保留草稿编辑并暂停发送，Enter 允许一次、Escape 拒绝，输入法确认不触发决定。正文与输入卡片共用自适应宽度（正文 680–920px，窄面板按可用空间收缩），输出区对称预留滚动条空间；28px 附件按钮与 34px 发送、停止按钮在主对话和侧边对话保持一致。

工具摘要使用弱化的扳手图标与动作短句，例如「读取了文件、修改了文件、运行了命令」，同类操作只描述一次。正常完成不重复展示数量和勾选，次数保留在悬停提示；折叠箭头在悬停、键盘聚焦或展开时显示，触屏始终显示。生成中显示当前动作，失败和中断保持可见；全部失败的修改描述为「尝试修改文件」，不宣称文件已经修改成功。轮次完成后顶部仅显示用时，仍可统一控制展开。

会话侧栏支持搜索、进行中筛选和后台生成状态，小屏使用抽屉导航。

工作流首页用卡片展示用途与可用状态，支持搜索和可运行筛选。展开卡片后按需读取源码并预览节点图；编辑入口打开流程图/代码详情。在线运行入口将参数表单打开在当前工作空间对话，主、侧边对话的 `/` 选择也留在原对话；填写后发送明确的运行请求，由同一 Agent 调用已发现的 Flow，仍可继续聊天。表单保留原文字和附件草稿，运行卡片共用完整输入、步骤、产物、插件结果与控制组件；「再次运行」回填原输入，发送后创建独立 Run。导入、导出和草稿操作在编辑视图中提供。

旧绑定 Flow 的会话保留执行记录与原直接运行入口；同一服务在线时可点击「继续对话」，将近期原输入摘要、运行 ID 和状态带入持久化工作空间对话，后续查询读取原 Run，不自动重跑。历史上下文限制最近 12 条记录、每条 1000 字符，完整输入和结果仍从原 Run 读取。演示模式继续使用原直接运行表单。新对话 Run 的 `conversationId` 随后端记录持久化，工作台不再为它自动导入第二个绑定 Flow 会话；旧记录原样读取。

目录统一轮询 `/flows/catalog`。选中 Flow 时按需读取 `/flows/:flowId/source`，切换会取消旧请求，版本 hash 变更会更新预览。节点图自动适应画布，节点详情点击后浮出并可关闭。运行页不再重复列出 Flow，运行记录仅显示当前 Flow；参数草稿在已注册 Flow 之间切换时保留。

会话各自保留当前访问期间未发送的消息草稿。每个会话持有独立取消控制器，切换不会停止其他会话，停止只影响当前会话。已有 `aura.workspace.v1` 持久化格式保持兼容；刷新后正在生成的回复仍恢复为「已停止」。

打开旧对话或新建对话时优先选择默认工作空间；服务未返回默认标记时，与初次加载一致地选择已有工作空间。工作空间列表加载中、为空或读取失败时仍保留历史和可编辑输入框，只暂停发送；选择或新建工作空间后可继续，列表加载完成不重建输入框或清空草稿。

工作空间使用单行 48px 顶栏：左侧为标题、对话 / 执行记录切换和工具面板入口，右侧同一高度放通用工具标签。工具面板的「＋」支持新建侧边对话、终端；标签使用任务标题或 shell 名，多标签可通过列表菜单与方向键切换。收起按钮立即隐藏面板，网络失败也可用；切换和收起保留草稿及运行任务。标签「×」关闭对应工具，失败时保留并提示。

侧边对话跟随主会话，多个对话各自保留模型、草稿和历史。「带回主对话」将已有结论追加到主对话草稿，由用户审阅后发送；不会额外请求模型或自动关闭侧边对话。终端跟随工作区，同工作区切换主对话不会重建进程。真实 PTY 经 DSH 的公开 subprocess 接口启动，Windows 优先 PowerShell 7，找不到时使用 Windows PowerShell，其他平台使用系统 shell。前端按需加载 xterm.js，支持 ANSI、持续输入、Ctrl+C、调宽和多终端。输出通过带游标的 SSE 同步，断线重连与刷新附着到原进程；关闭活动状态无法确认或仍有任务的终端，需要先确认结束进程。服务重启后终端不自动重建，也不会重新执行旧命令。

旁支按主会话持久保存在后端索引中，刷新或重启 Aura 后恢复旁支及历史（未发送草稿只保留当前访问期间）。旧的单旁支记录直接兼容读取，不执行数据迁移。只有主动关闭旁支、关闭主会话或归档主会话时才丢弃对应旁支关联；取消归档不会恢复旧旁支。DSH 会话日志本身不删除。

主对话与工具面板之间支持拖拽调宽，两侧至少保留 320px。分割线支持方向键微调、Home/End 调至边界、双击恢复默认，拖拽时按 Esc 可取消。宽度继续在本机 `aura.coding.side-width` 中记忆，不迁移旧布局配置；可用区域不足 648px 时，打开工具面板会切换为全宽工具视图，收起后返回主对话。调整布局不会重建对话或丢失草稿。长代码、宽表格及展开的 diff 只在各自内容块内横向滚动，不会撑宽整条消息或小结。

Flow 代码草稿以 `aura.flow-draft.v1` 自动保存在本机，支持代码编辑、导入、导出和撤销替换。默认流程图在浏览器中静态解析源码，不执行用户代码，只显示输入、输出、`ctx.agent`、`ctx.action`/工具调用、`if`/`switch` 和循环；变量处理、格式化、日志及辅助函数不会生成节点，但调用前后的执行顺序会保留。`Promise.all` 显示为并行步骤，节点可定位到对应代码行。

生成助手通过现有 DSH 对话链路接收当前代码上下文，完整的 `defineFlow` 代码块提供「放入 Flow 编辑器」操作，应用后直接刷新流程图；本地演示模式不调用真实模型。上下文最多附带前 9000 字符，并明确标注截断。

本地草稿与后端已注册的 Flow 是独立状态。后端 API 提供当前已注册版本的入口源码预览、目录、运行、取消和历史，不提供源码发布接口；导出的 `my-flow.flow.js` 需要按编排包规则注册到后端。可通过更多菜单将已注册代码复制到本地草稿编辑，运行仍使用后端已注册版本。

设置页的「外部插件坞」通过当前 runtime 的 `/plugins/config` 管理受信任的本地插件目录。新增目录默认关闭；保存后显示清单、SDK 和引擎兼容性的后端校验结果，并把有效目录立即应用到新运行。已有运行继续使用创建时固定的插件版本；配置文件若在 Aura 外部发生变化，页面会提示重新保存应用。界面不会安装插件依赖，也不会把该能力开放给绑定局域网地址的 runtime。

侧栏的 Site 菜单仅在 Electron 桌面宿主中启用本机项目运行器。选择包含 `package.json` 的前端项目目录后，后端会识别包管理器和 `dev`/`start`/`serve` 脚本；只有确认预览端口属于本次进程且 HTTP 就绪，才在独立窗口打开。支持的直接开发命令会先选择可用端口再启动，并把实际地址同步到页面；自定义命令冲突会报错。运行中锁定目录、脚本和地址，就绪超时仍保留停止按钮；「打开预览」仅在后端验证就绪后启用。共享 DTO 属于 `@aura/protocol/types`，frontend 不包含端口或进程操作。目录、脚本和预览地址保存在 `aura.site.v1`，不会进入会话、HTTP 请求或凭据存储；退出 Aura 会停止该项目进程。浏览器和移动端只显示桌面版提示。

验证命令：`pnpm --filter @aura/workbench typecheck`、`pnpm --filter @aura/workbench test`。宽内容布局回归使用本机 Chrome；其他平台可通过 `CHROME_BIN` 指定 Chrome/Chromium 可执行文件，未提供可用浏览器时只跳过该项。当前结果见 [验证记录](../../../docs/verification.md)。
