# @aura/workbench

侧栏、菜单、输入框、设置、记录、工作流、自动化与工作台页面共用主题文字色阶和基础排版。普通文字与输入值为 400 字重，默认加粗和标题为 600，组件已有的 500 字重层次保留。输入占位文字统一使用 `muted` 且不额外衰减透明度，悬浮提示使用 `tooltipText`。宿主根节点与外部模态层所在的文档使用同一套字体抗锯齿。

宿主入口加载公开的 `@aura/ui/icons.css`，侧栏、菜单、表单、工具栏、插件页面和模态层共用图标描边与色阶。普通 Lucide 图标为 1.6 描边，发送箭头使用 `aura-icon--emphasis`，实心停止符号使用 `aura-icon--filled`，大号占位图标使用 `aura-icon--display`。颜色沿父级语义或公开色阶类继承，禁用透明度由控件承担；流程连线、品牌图形与媒体画布保留自身几何。`icon-styles.test.ts` 验证深浅主题中的宿主/插件继承、模态层、语义颜色、实心形状、自定义图形和单层禁用反馈。

页面布局按 `.workspace-main` 的实际可用宽度响应，窗口缩放、侧栏展开或拖宽都会触发布局调整，无需刷新。主区不超过 820px 时，设置分类改为横向滚动导航，自动化详情独占主区；设置表单按其自身滚动区宽度在 600px 以下切成单列。工作流卡片、参数和记录筛选在窄区域自动换行，嵌套工作流的输入输出按所在面板宽度排列。内容保留阅读宽度上限，滚动容器始终铺满主区。普通菜单在窗口或所属区域变化时重新定位，提示气泡在缩放、滚动时关闭，弹窗限制在视口内并允许内部滚动。`responsive-layout.test.ts` 覆盖宽窗口中的 960→720→560→320→960px 内容区变化与恢复，以及窄面板中的工作流结果。

性能与资源生命周期：工作台和工作流列表作为轻量导航页面随主界面加载，点击不经过整页 Suspense；工作流图表和编辑器分别按需拆包，未打开时不下载、不挂载。设置、记录与自动化继续按需加载，等待只影响内容区，侧栏和顶栏保留。目录使用 ETag 条件请求，正常每 15 秒校验，窗口重新可见时立即校验；未就绪时短间隔重试，后台窗口暂停目录请求。文件 diff 按 hunk 对象弱引用缓存，已完成回合独立 memo，计时只更新运行回合。

模型目录在本地状态恢复后与工作空间记录、对话模块并行读取，按服务地址与模式共享请求及一分钟的内存缓存；主、旁支输入框和重复访问不清空已就绪的目录。最后一个订阅离开时取消未完成请求，切换服务不混用结果；保存模型设置使对应缓存失效并立即更新。只读启动请求对连接拒绝和 503 在五秒窗口内短间隔重试，不用于模型执行或授权写入。

`startup-cache.ts` 将成功读取的公共模型目录、工作空间与对话目录投影到独立的 `aura.startup-cache.v1` 客户端缓存，重开窗口先恢复选择和侧栏标题，再读后端校验；按服务地址与模式隔离，七天过期、最多 16 组模型目录、8 组工作空间与对话目录快照，每个工作空间缓存最近 200 条对话，总长度限制为一百万字符。对话目录只保存 ID、归属、标题、时间和归档标记，不缓存凭据、账号、对话正文、工具结果、执行状态或模型设置；含认证信息的服务 URL 不缓存，损坏、过期和存储失败不阻塞在线读取。未完成读取的列表显示加载中，读取失败提供重试，不提前显示为空；空列表和移除的工作空间会清除对应缓存，状态轮询不会反复写入未变化的标题。保存模型设置同时删除对应落盘模型缓存。该缓存可丢弃，不改写或迁移 `.aura/` 的持久化格式。

有缓存工作空间时，新任务可以在服务连接期间先提交；界面显示等待状态并允许停止。提交固定当时显示的模型及思考强度，先用可取消的只读列表确认工作空间仍有效，再发送一次模型 POST；初始化失败、目录失效或取消不会发送，模型请求失败不自动重试。新建会话的选择会保留到校验结束，后台目录更新不会切换已提交请求的模型。没有缓存的首次访问仍等待真实目录，已有会话仍需要读取历史。

桌面就绪回调只等待本地状态和首屏模块提交，服务读取不阻塞启动层退出。底部在初始授权、工作空间或模型尚未准备好时显示准备状态；已有模型缓存的后台更新不回退为准备中。导航与在线草稿可提前使用，缺少工作空间时禁止发送；初始演示界面等待授权确认后才允许输入和发送，防止自动升级为在线模式时丢失演示草稿。取消的授权读取不会提前结束当前初始化状态。

启动时的会话列表使用 `status=metadata`，先恢复标题、模型设置和旁支关联，并携带服务内存中正在运行或等待回答的状态；不为每一条旧记录打开历史日志。模型读取完成后再于后台补充已结束会话的历史状态，失败保留已有记录与已知状态，后台回填和活动轮询不作为启动完成条件。

对话历史使用 DSH 稳定游标向前分页，界面每次显示最多 40 轮，并提供较早、后续及返回最新操作；最多缓存六段最近访问的对话，当前和正在执行的对话始终保留。旁支首次打开才读取历史，隐藏且无运行任务、无附件 60 秒后释放界面，保留草稿；切换不会停止执行。Run 由 `workflow-run-store.ts` 按 endpoint 与 Run ID 共用读取、取消和轮询，未变化快照保持引用稳定，最多保留 50 个无订阅缓存。

历史读取的加载与错误状态按会话归属，切到新任务或已加载的会话不会继承旧请求的等待和发送限制；过期响应不会覆盖当前会话。单次历史 HTTP 读取限制八秒，超时或失败显示独立重试入口并保留草稿，已有会话须读取成功后才继续发送；切换会话会取消旧的前端请求。

Site 页面及项目列表状态已迁到 `plugins/site-launcher/client/src/`。工作台通过 DSH 页面贡献加载它们，不再硬编码业务页面。`src/screens` 保留通用对话、工作流与设置；工作区、导航兼容映射和宿主适配留在根模块。`@aura/workbench/plugin` / `transport` 提供公开的通用工作流控件、JSON/媒体传输及原生目录/预览适配，插件不导入私有源码。目录职责见 [模块边界](../../../docs/development/module-boundaries.md)。

浏览器、Electron 与 Capacitor 共用的 Aura React Web 工作台，包含界面、导航、交互状态、Web Storage 和 HTTP transport。应用只提供 React DOM 运行时及少量宿主能力；本包只依赖 frontend/shared 库，不读取后端凭据，也不启动 DSH。

移动端入口位于 `apps/mobile`，桌面端入口位于 `apps/desktop`。两端复用同一个 `App` 导出，平台启动、窗口和发布配置留在各自应用中。

`App` 可接收宿主的 `onReady` 回调：本地状态恢复、首屏模块加载并提交后，通知当前外观和减少动态效果设置。后端请求不属于启动门槛，模块错误交由宿主的错误边界呈现。桌面入口用它结束独立启动动画，Web 和移动端可省略回调。

## 紧凑工作台

追加消息未被接收时，工作台保留草稿和附件，并查询会话状态。服务仍在收尾时继续等待，确认本轮结束后，用户可再次点击发送开启新一轮。状态读取失败时，下一次点击先重新确认状态。

粘贴、拖入或选择的图片会立即上传。上传失败时，缩略图显示感叹号，输入框上方显示对应文件和失败原因。

输入、搜索、路径和对话卡片的焦点统一使用主题紫色细边、淡紫渐变与柔光；复合控件只在外层高亮，避免内部输入叠出方框。设置、自动化、工作流表单与目录搜索复用同一组焦点变量，菜单、模型选择、导航和筛选项共用柔紫渐隐底色与顶部微光。效果变量在 `styles.css` 的 `.aura-root` 中从现有主题色派生，随深浅主题切换；禁用、错误与危险操作保持各自语义，减少动态效果与强制颜色模式分别取消过渡和使用系统轮廓。

按钮的悬停、按下、选中与键盘焦点共用主题渐变及外光、内阴影；主按钮和发送按钮保留白色前景，危险操作使用红色效果。设置、插件与工作流开关共用开启渐变、悬停微光和按下反馈，关闭时保持中性轨道；触屏不使用按钮悬停反馈，减少动态效果同时停用滑块过渡。组合行通过 `data-row-highlight` 持有整行背景与焦点，其内部 `row-control` 按钮保持透明，覆盖侧栏、工具标签、全部记录、工作流摘要和文件列表；行内菜单打开时继续高亮原行，避免标题与操作区之间出现圆弧或重叠背景。独立开关、选择标记和语义状态保持原有反馈。

macOS 桌面宽窗口（≥900px）将顶部导航、页面标题和工具标签合并到同一行 48px 标题区，左侧保留原生红绿灯与导航位置；收起侧栏后标题自动让位，标题留白可拖动，按钮仍可点击。其他宿主及窄窗口保留上下分行布局。顶部导航栏只保留后退、前进与唯一的侧栏开关，小屏展开抽屉时也沿用同一组导航。所有后端模式的页面顶栏均不展示登录按钮或模型服务连接徽标；账号授权留在设置的「模型与账号」，模型选择留在输入框菜单。侧栏顶部只保留「新任务」，下方是带动态图标的 Aura 个人助手，再接工作流、自动化任务与工作台；移除品牌行和重复的对话导航。应用级命令统一从侧栏左下角「本地工作区」菜单进入，包含工作流、重命名、复制对话、外观、已归档会话和设置；复制结果使用通知提示。小屏菜单在侧栏抽屉内展开，支持键盘关闭与焦点恢复。

Aura 入口始终打开后端同一个主会话，与普通任务分开，不重复列入工作空间文件夹和全部记录。首次显式点击通过 `POST /coding/assistant` 打开或创建；刷新恢复使用只读 GET，不自动新建或发送消息。加载时入口保持可点击，连续点击共用请求。同一窗口切回 Aura 时复用已加载的会话和历史记录。当前助手视图按服务地址在本机记忆，历史与模型选择由后端持有；未发送文字草稿与图片附件在当前访问期间按会话保留，上传过程中切换也不会混入其他会话。助手绑定首次创建时的默认工作空间，不随任务切换，普通关闭、归档和删除接口拒绝操作。动态图标在生成时加快轨道旋转，系统或应用「减少动态效果」会停止动画。

输入框的 `/` 与「＋ → 命令、Skills 和 Flows」共用一个菜单，按「内置命令 / Skills / Flows」逐级展开，输入关键词时搜索三类项目。内置命令提供模型选择、停止当前生成和清空输入；Skills 读取当前工作空间的 DSH 用户可调用目录，选中后插入 `/name `，继续填写任务再发送；Flows 打开现有参数表单。菜单与整个输入卡片左对齐，以 400px 宽的紧凑浮层显示并受视口约束，始终在卡片上方留出间距，列表单独滚动。搜索框使用完整圆角细边反馈焦点，避免叠加全局方框轮廓；柔紫选中态、等宽计数和底部键盘提示沿用主题语义，触屏扩大操作并隐藏键盘提示。方向键、Enter/Tab、返回按钮和 Esc 均可操作；关闭菜单保留草稿。

主对话和旁支输入框的权限菜单提供「只读」「工作区写入」「完全访问」。「完全访问」以红色标识，并提示无沙箱限制且无需审批。新任务草稿的选择在首条消息提交时保存。已保存对话的选择在切换时写入服务，运行中的对话从下一次受限工具调用开始使用新权限。旁支在单独选择之前跟随主对话。新分叉在首轮继承来源已选的权限，也可在发送前另选。

输入框默认使用执行模式。在草稿开头选择「计划模式」或「目标模式」，会插入行内的 `/plan` 或 `/goal` 命令标签。发送带正文的命令才会启用对应模式。光标贴着标签时，按一次 Backspace 或 Delete 选中标签，再按一次移除，正文可以继续编辑。Skill 引用可以在正文中插入，按普通文字编辑和删除。

发送 `/plan <任务>` 后，输入框下方显示当前会话的计划状态，使用 `/plan off` 退出。Agent 提交计划后，可以通过审阅卡批准执行或反馈修改。

发送 `/goal <目标>` 将纯文本正文设为目标。目标在同一会话按 DSH 的轮次上限自动续跑，每次模型请求占用「对话能力」设置中的额外请求额度。目标卡显示状态和轮次，可暂停、继续或清除。连接中断或服务重启后，用户可手动继续。主对话和旁支分别维护自己的目标。

主对话与侧边对话共用独立加载的输入卡片样式：24px 圆角、上方输入、下方操作。新旧对话均置底，主、旁支输入卡片底边对齐；空草稿使用相同高度，多行草稿向上增高。「带回主对话」位于旁支输入框上方。左侧「＋」收纳图片和工具入口；从侧栏顶部点「新任务」时，输入框左下角可选择或新建工作空间。从工作空间行点「新会话」时，草稿直接绑定该工作空间，输入框隐藏选择器。首次发送后，后续对话沿用任务已绑定的工作空间；打开历史任务、旧对话或 Aura 助手也隐藏选择器。右侧显示模型、思考强度与圆形发送按钮；模型菜单内切换 Codex、Lumina、自定义 API 或演示服务。输入框自动增高到 220px 后内部滚动，窄卡片收起思考强度文字并截断长名称。右侧仅显示一个操作按钮：生成中空草稿显示停止，填写文字或添加图片后切换为发送；图片上传期间发送置灰。模型和思考强度可在当前服务内调整；追加消息固定发送时的选择，在后续模型调用中生效，已经发出的请求继续使用原配置。发送失败保留草稿和附件，不自动重试；跨模型服务切换在本轮结束后操作。

输出区按事件时间线交错显示 AI 文字、工具组、问题、用户引导和嵌套工作流。连续工具调用合并为可独立展开的摘要，展开后可查看单项和文件差异。正常完成时，状态行显示耗时和工具调用次数，默认收起工具组、任务进度、阶段回复和文件改动。最终回复直接展示 Agent 原文，问答、引导、来源、工作流结果和交付文件继续显示。没有最终回复时只显示已有状态和记录。点击状态行可展开执行记录。失败、停止和开始输出后收到用户引导的轮次保留过程。历史回放采用同样的规则。

运行中发送的追加消息立即进入时间线，显示「等待 Agent 读取」。收到对应请求 ID 的读取事件后，原消息移除提示。后端确认接收时清除已提交的内容，提交期间新输入的草稿和新添加的附件继续保留。

运行中的最早一批未答问题或审批使用底部决策卡片，输出区在决定后保留记录。普通问题暂时接管输入区，保留草稿和停止操作，回答后可在输出区展开查看。等待审批时仍可编辑草稿，Enter 允许一次、Escape 拒绝，输入法确认不触发决定。两种卡片等待期间都暂停发送。正文与输入卡片共用自适应宽度（正文 680–920px，窄面板按可用空间收缩），输出区对称预留滚动条空间；28px 附件按钮与 34px 发送、停止按钮在主对话和侧边对话保持一致。

对话面板与主滚动区铺满可用区域，滚动条贴所属面板右边缘；居中限宽只作用于正文与输入卡片。该布局由共享样式提供，不依赖演示对话页的按需加载样式。

工具组使用弱化的扳手图标与动作短句，例如「读取了文件、修改了文件、运行了命令」，同类操作只描述一次。工具组调用次数保留在悬停提示；折叠箭头在悬停、键盘聚焦或展开时显示，触屏始终显示。生成中显示当前动作，失败和中断保持可见。全部失败的修改显示为「尝试修改文件」。

会话侧栏支持搜索、进行中筛选和后台生成状态，小屏使用抽屉导航。

宽屏侧栏用 220ms 滑动过渡带动主区移动，收起后保留搜索和分组状态，隐藏控件退出键盘焦点顺序。拖拽手柄时宽度实时跟手。窄屏抽屉用同一节奏滑入和滑出，遮罩同步淡变，关闭后焦点回到侧栏开关。工作台菜单打开时短暂淡入。系统或应用开启「减少动态效果」时直接切换。

工作流首页用卡片展示用途与可用状态，支持搜索和可运行筛选。展开卡片后按需读取源码并预览节点图；编辑入口打开流程图/代码详情。在线运行入口将参数表单打开在当前工作空间对话，主、侧边对话的 `/` 选择也留在原对话；填写后发送明确的运行请求，由同一 Agent 调用已发现的 Flow，仍可继续聊天。表单保留原文字和附件草稿，运行卡片共用完整输入、步骤、产物、插件结果与控制组件；「再次运行」回填原输入，发送后创建独立 Run。导入、导出和草稿操作在编辑视图中提供。

旧绑定 Flow 的会话保留执行记录与原直接运行入口；同一服务在线时可点击「继续对话」，将近期原输入摘要、运行 ID 和状态带入持久化工作空间对话，后续查询读取原 Run，不自动重跑。历史上下文限制最近 12 条记录、每条 1000 字符，完整输入和结果仍从原 Run 读取。演示模式继续使用原直接运行表单。新对话 Run 的 `conversationId` 随后端记录持久化，工作台不再为它自动导入第二个绑定 Flow 会话；旧记录原样读取。

目录统一轮询 `/flows/catalog`。选中 Flow 时按需读取 `/flows/:flowId/source`，切换会取消旧请求，版本 hash 变更会更新预览。节点图自动适应画布，节点详情点击后浮出并可关闭。运行页不再重复列出 Flow，运行记录仅显示当前 Flow；参数草稿在已注册 Flow 之间切换时保留。

会话各自保留当前访问期间未发送的消息草稿。每个会话持有独立取消控制器，切换不会停止其他会话，停止只影响当前会话。已有 `aura.workspace.v1` 持久化格式保持兼容；刷新后正在生成的回复仍恢复为「已停止」。

打开旧对话或新建对话时优先选择默认工作空间；服务未返回默认标记时，与初次加载一致地选择已有工作空间。工作空间列表加载中、为空或读取失败时仍保留历史和可编辑输入框，只暂停发送；选择或新建工作空间后可继续，列表加载完成不重建输入框或清空草稿。

工作空间使用单行 48px 顶栏：左侧为标题、对话 / 执行记录切换和工具面板入口，右侧同一高度放通用工具标签。工具面板的「＋」支持新建侧边对话、终端，桌面端还可以新建浏览器。多标签可通过列表菜单与方向键切换。收起后焦点回到入口，切换和收起保留草稿、运行任务和浏览器页面。浏览器标签与 DSH 右侧栏一致，归属打开它的主会话：切到其他会话时隐藏但保持挂载，切回后页面与历史仍在；新任务草稿中打开的浏览器在首次发送后归入新会话。标签「×」关闭对应工具，失败时保留并提示。

桌面浏览器支持 HTTP(S) 网页与本地站点预览，提供地址栏、前进后退、刷新和在系统浏览器打开。工具面板按会话记住浏览器标签、当前选中的工具和面板开合状态。应用重启后显示上次的标签名称和地址，由用户选择恢复网页。浏览器的站点数据在应用退出时释放。

顶部侧栏开关使用 `aria-expanded` 表达展开状态，常态保持透明，悬停、按下和键盘焦点提供主题反馈。macOS 合并标题栏的原生拖拽区域必须避开导航按钮：侧栏顶部与收起侧栏后的内容标题栏只在导航区域右侧接受拖拽，避免后绘制的背景热区拦截按钮点击。

侧边对话跟随主会话，多个对话各自保留模型、草稿和历史。「带回主对话」将已有结论追加到主对话草稿，由用户审阅后发送；不会额外请求模型或自动关闭侧边对话。终端跟随工作区，同工作区切换主对话不会重建进程。真实 PTY 经 DSH 的公开 subprocess 接口启动，Windows 优先 PowerShell 7，找不到时使用 Windows PowerShell，其他平台使用系统 shell。前端按需加载 xterm.js，支持 ANSI、持续输入、Ctrl+C、调宽和多终端。输出通过带游标的 SSE 同步，断线重连与刷新附着到原进程；关闭活动状态无法确认或仍有任务的终端，需要先确认结束进程。服务重启后终端不自动重建，也不会重新执行旧命令。

旁支按主会话持久保存在后端索引中，刷新或重启 Aura 后恢复旁支及历史（未发送草稿只保留当前访问期间）。旧的单旁支记录直接兼容读取，不执行数据迁移。只有主动关闭旁支、关闭主会话或归档主会话时才丢弃对应旁支关联；取消归档不会恢复旧旁支。DSH 会话日志本身不删除。

主对话与工具面板之间支持拖拽调宽，两侧至少保留 320px。分割线支持方向键微调、Home/End 调至边界、双击恢复默认，拖拽时按 Esc 可取消。宽度继续在本机 `aura.coding.side-width` 中记忆，不迁移旧布局配置；可用区域不足 648px 时，打开工具面板会切换为全宽工具视图，收起后返回主对话。调整布局不会重建对话或丢失草稿。长代码、宽表格及展开的 diff 只在各自内容块内横向滚动，不会撑宽整条消息或文件改动列表。交付文件的长路径以省略号收缩显示，悬停可查看完整路径，复制和定位按钮始终保留在卡片内。操作反馈在文件行下方自动换行，不挤占路径和按钮。桌面端可定位任意本机目录中已存在的普通文件；绝对路径直接定位，相对路径按项目目录解析。

工作流生成助手与自动化任务详情沿用侧栏过渡。宽屏时主区随面板边缘调整，窄屏时右侧视图滑过原内容。减少动态效果时直接切换。

Flow 代码草稿以 `aura.flow-draft.v1` 自动保存在本机，支持代码编辑、导入、导出和撤销替换。默认流程图在浏览器中静态解析源码，不执行用户代码，只显示输入、输出、`ctx.agent`、`ctx.action`/工具调用、`if`/`switch` 和循环；变量处理、格式化、日志及辅助函数不会生成节点，但调用前后的执行顺序会保留。`Promise.all` 显示为并行步骤，节点可定位到对应代码行。

生成助手通过现有 DSH 对话链路接收当前代码上下文，完整的 `defineFlow` 代码块提供「放入 Flow 编辑器」操作，应用后直接刷新流程图；本地演示模式不调用真实模型。上下文最多附带前 9000 字符，并明确标注截断。

本地草稿与后端已注册的 Flow 是独立状态。后端 API 提供当前已注册版本的入口源码预览、目录、运行、取消和历史，不提供源码发布接口；导出的 `my-flow.flow.js` 需要按编排包规则注册到后端。可通过更多菜单将已注册代码复制到本地草稿编辑，运行仍使用后端已注册版本。

设置页的「外部插件坞」通过当前 runtime 的 `/plugins/config` 管理受信任的本地插件目录。新增目录默认关闭；保存后显示清单、SDK 和引擎兼容性的后端校验结果，并把有效目录立即应用到新运行。已有运行继续使用创建时固定的插件版本；配置文件若在 Aura 外部发生变化，页面会提示重新保存应用。界面不会安装插件依赖，也不会把该能力开放给绑定局域网地址的 runtime。

侧栏的 Site 菜单仅在 Electron 桌面宿主中启用本机项目运行器。选择包含 `package.json` 的前端项目目录后，后端会识别包管理器和 `dev`/`start`/`serve` 脚本；只有确认预览端口属于本次进程且 HTTP 就绪，才在独立窗口打开。支持的直接开发命令会先选择可用端口再启动，并把实际地址同步到页面；自定义命令冲突会报错。运行中锁定目录、脚本和地址，就绪超时仍保留停止按钮；「打开预览」仅在后端验证就绪后启用。共享 DTO 属于 `@aura/protocol/types`，frontend 不包含端口或进程操作。目录、脚本和预览地址保存在 `aura.site.v1`，不会进入会话、HTTP 请求或凭据存储；退出 Aura 会停止该项目进程。浏览器和移动端只显示桌面版提示。

验证命令：`pnpm --filter @aura/workbench typecheck`、`pnpm --filter @aura/workbench test`。宽内容布局回归使用本机 Chrome；其他平台可通过 `CHROME_BIN` 指定 Chrome/Chromium 可执行文件，未提供可用浏览器时只跳过该项。当前结果见 [验证记录](../../../docs/verification.md)。
