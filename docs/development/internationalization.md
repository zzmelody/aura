# 界面多语言

Aura 使用 i18next + react-i18next，共用前端包 `@aura/i18n`。语言为简体中文、英文、日文、韩文、俄文、法文，默认跟随系统；用户可在设置的外观页选择语言，选择保存在独立的本机界面偏好中。

## 边界

界面语言只控制宿主与插件界面文案、无障碍标签、状态通知和显示格式。用户文本、工作区/会话名称、模型 ID、路径、脚本名、日志和 AI 生成内容保持原值。切换语言不写入 `.aura/`，不改写历史，不触发模型请求。AI 回复语言是独立功能，不应通过翻译界面时隐式修改系统提示词。

宿主目录按页面领域放在 `packages/frontend/workbench/src/locales/<locale>/<namespace>.json`。页面模块注册自己需要的资源；以英文为回退，完整句子使用插值和语言对应的复数形式。时间与数字通过 `Intl`，保留业务指定的时区、币种与精度。

插件自带资源，通过公开 `auraWorkbench.translations()` 注册，使用 `usePluginTranslation(pluginId)` 订阅同一个语言运行时。页面标题使用可选的 `titleKey`、`descriptionKey`，原字段继续作兼容回退。插件资源不得覆盖宿主 namespace，卸载时清理。

运行状态与通知保存语义键/消息引用；只有展示时解析为当前语言。存储中的工作流旧状态文本与 AI 上下文保留既有格式，界面可从状态枚举投影显示。

产物列表、预览弹窗、图片缩放和 3D 查看器状态已接入。文件大小和百分比使用本地格式，保留原有计算阈值与精度；文件名、下载地址和媒体内容保持不变。切换语言不替换图片或模型元素、不重建查看器、不重置视角或预览选择。

工作流编辑器与 SVG 画布已接入，导入通知、保存失败与分析错误在展示时翻译。切换语言保留草稿、撤销记录、打开的菜单、分析标识、SVG 节点和手动缩放；不会重新分析或触发草稿自动保存。源码、入门示例和发给 Agent 的分析提示词保持原文。

侧栏与对话分隔条的无障碍提示、选中文字工具条已接入。拖动过程中切换语言仍读出当前宽度，只有结束拖动或键盘调整才保存；选中文字工具条保留选区与焦点，并根据翻译后的尺寸重新定位、在窄屏换行。插件脚本加载、模块图读取、页面渲染和目录读写的本地错误保存消息引用，界面语言变化不重启插件、不重复请求或再次尝试渲染失败的页面。DSH 聚合脚本错误时，宿主在加载边界保留消息引用；第三方插件的原始错误继续按原文显示。

会话传输、工作区/旁支列表、本地历史读写和 Flow 目录的本地错误已接入，工作流提交与取消的本地回退提示也随语言变化。HTTP 错误保留状态码，超时通过语义键识别；取消信号和底层错误原因保持不变。未确认命令仍保留原 ID、模式和输入，切换语言不重发、查询或写入历史。公开 `WorkflowApiError` 保留既有状态码、`Error.name` 和可读 `message`，同时允许宿主从错误对象提取可翻译引用。

桌面启动页、原生文件/目录选择框和应用启动/退出提示已接入，应用词库放在 `apps/desktop/src/locales/`。启动页在 React 加载前读取已有语言偏好，工作台就绪后接管文档标题；主进程先按系统语言显示，之后只通过受限 IPC 接收工作台的有效 locale，不另存配置。语言变化不重建启动画布或重开原生选择框，路径、过滤条件和取消语义保持不变。系统提供的按钮由操作系统本地化，已经打开的原生对话框在下次打开时应用新语言。

公开上传、工作流、插件调用和路径选择的本地错误已接入；`@aura/plugin-ui 0.3` 提供消息引用的提取与渲染，Site/Tripo 保存的失败及登录弹窗拦截提示可随语言更新。旧插件仍能读取可读的 `Error.message`。桌面 IPC 使用参数为空的稳定错误码，公开前端适配器恢复可翻译 Error；保留成功值、取消、路径规则和浏览器租约，不传播底层异常或私有路径。

后端错误的增量契约已接通：`CodedFlowError` 通过 DSH RPC 和各 HTTP 错误边界保留稳定 code、受限 params 及旧 message/status。编排启动/关闭/断连、Flow 请求校验、上传大小与类型、图片/产物服务不可用等已接入，前端使用 `apiErrors` 六语言目录，保留的错误在展示时解析。已知码只接受声明的有界数值和格式受限的模型／原因标识；未知码回退到原 message，不从句子推断错误类型。旧 FlowError、请求 ID、取消和执行策略保持兼容，不自动重发付费或未知结果请求。

模型服务检查通过可选 `checkDetails` 区分未检查、列表同步与实际模型请求的成功/失败，界面保存消息引用并显示六语言结果与复数计数。认证、权限、地址、限流、空回复、不支持、超时/取消与一般失败使用受控原因；模型 ID 和成功回复保留原值，探测提示词不随界面语言变化。旧 `checks` 字段仍兼容，未知结果回退原文；检查结果不持久化，切换语言不保存配置或重复请求。

Site 后端运行状态使用可选 `messageDetails` 与 `portDetails`，由插件校验已知码和参数后翻译。覆盖端口检查/占用/选择、启动与停止、进程退出、预览打开与超时及启动前校验；旧消息保留作兼容回退。脚本名、端口值、本机地址和进程输出不翻译，描述符不写入项目存储，不因语言变化启动、停止或重试进程。长状态文本在窄容器内换行。

旧对话和编码 NDJSON 接口已接通语义错误；原有纯文本 HTTP 拒绝通过 `X-Aura-Error-Code` 附加语义，保持原正文和状态。对话命令准入、执行冲突、索引与旁支、回答及历史游标的已知错误已接入。执行层以有界内存映射为回执、实时事件、快照和对应原生失败回合附加 `errorDetails`，前端保存消息引用。切换语言保留草稿、回答、连接和未确认命令，不重发或改写历史。命令账本 schema、持久化记录及 DSH 上下文保持不变；映射淘汰或进程重启后，仅靠该映射识别的已完成错误回退原文，未完成执行的重启提示从恢复状态投影。

模型执行的输出上限、额度用尽、Codex 续期失败、订阅拒绝、HTTP 失败和一般失败使用后端既有安全分类附加显示码，模型选项错误保留有界原因码。原生 DSH 历史中的失败与策略阻止在读取时投影相同详情，重启后也可翻译，不需要重写日志。旧错误前缀、消息、状态、付费预算与请求策略不变，不将上游正文加入翻译参数。

工作区目录与名称、默认工作区限制、终端退出与关闭确认、会话请求校验、协作目标、对话能力预算、设置 revision 和外部集成的已知拒绝已接入稳定错误码。自动化按 DSH 原生输入错误码翻译任务名称/指令、时间规则、时区、未来时间、范围、频率和目标会话校验，并区分任务冲突与不存在。原任务内容、时间与时区、配置校验、终端控制和付费预算行为保持不变。

会话工具与维护阶段的已知拒绝已接入，包括父会话、MCP 权限、子 Agent 目录、Web 配置、协作初始化、压缩结果未知、图片支持、目标纯文本与额度、分叉记录及运行中跨服务切换。原取消原因和安全提示保持兼容，不影响工具权限、输入、执行或付费请求策略。

Flow 运行控制、检查点与人工处理、子运行操作、重复请求、历史 attempt、产物不存在/预览/文件读取，以及插件配置加载/回滚失败的已知拒绝已接入稳定错误码。原消息和状态码保持兼容，描述符不写入运行记录或插件配置；拒绝操作不会改变已完成记录。

Flow 执行的已知模型/Action 失败、一般代码失败和超时通过最多 1024 条的运行时显示映射投影到运行、步骤和 attempt，人工确认警告与失败原因一起翻译。执行和存储继续使用原记录；只有返回给界面的副本携带 `errorDetails`。重启或淘汰后回退原消息，未知外部错误不从句子推断类型；草稿、输入、输出、历史和请求策略不因语言变化改变。

运行恢复的 memo/子运行认领、工具结果未知、记录核对、输出认领、重试预算、旧身份、模型配置与版本不兼容说明已接入。运行和步骤的恢复事件通过 `reasonDetails` 在显示副本中翻译；原说明、时间、状态与预算规则保持不变，不改写存档，也不从旧句子猜测类别。显式取消说明在已知操作分支投影。

标准 Schema 校验已接入：字段路径、类型要求、上下限、严格边界、未知字段及数据形式等通过结构化原因翻译。最多展示 32 项并以本地复数说明剩余数量；上下限和字节上限使用本地数字格式。原 `message` 保留完整诊断，不将输入值、枚举值或校验器原始消息作为翻译参数。自定义/未知原因及未知上下文保留原文；JSON 不可序列化与大小限制保留原状态码。Flow 的已知校验失败也可在运行界面随语言变化显示。

定义、工具注册和插件 HTTP 的已知拒绝已接入，包括贡献冲突、缺失定义、步骤/作用域 ID、源码行号、原生并发调用、嵌套/循环、固定版本、模型参数和超时。公开参数只允许有界的 ID、枚举、行号与数值；不传原始诊断、输入值或路径。目录的 `displayCatalog()` 单独附加错误详情，`catalog()` 与模型执行目录保持原字段，清理或替换问题时同步清理显示信息。

插件管理器的清单/包格式、入口与贡献目录、版本与权限、重复 ID、兼容性授权和配置读写诊断也提供稳定显示码。插件页面和目录设置可翻译失败说明与提示，保留原路径、错误字段和保存策略。显示详情从 DSH 执行状态中移除，仅恢复到仍匹配的公开状态，不因语言切换重做发现或配置保存。

HTTP 的请求校验、访问与大小限制、模型目录及模型配置失败已接入同一契约。Codex 登录的状态读取、设备码、回调端口、令牌交换、过期回调、输入校验和确认阶段通过后端既有分支提供显示标识，未知 DSH 通知仍保留原文。界面保留 HTTP 错误和授权状态的语义引用，不因语言变化重启登录、重复提交回调或重建轮询；原消息、状态码与凭据流程保持兼容。

Site 页面调用和 Tripo 的输入、配置、预算、付费结果未知与生成阶段错误由插件提供六语说明，宿主不包含业务词库。SDK 2.6 的 `ActionFailure` 可提供字面译文，调用内的私有回调将其加入显示投影，Error 对象、DSH 工具结果和持久化记录不带译文。页面/准入调用可抛出 `PluginFailure`；宿主校验大小并保留旧消息与状态。译文按当前界面语言选择，缺项回退英文，不执行模板或 HTML，也不重新发起操作。

中文、英文、日文、韩文、俄文和法文覆盖宿主界面、原生提示及随产品发布的插件。第三方插件未声明的文案、自定义校验指导、用户输入、源码、提示词、模型输出和历史原文继续保留；旧记录缺少显示标识时不从句子猜测类型，也不改写存档补标识。

自动化任务以当前语言显示星期、日期、时间和间隔，保持原计划的时间、时区与提交格式。命令菜单以翻译后的名称与说明搜索，`/plan`、`/goal` 等命令标识和用户的 Skill/Flow 名称保持原值。缓存的模型目录错误和表单校验提示在渲染时翻译，切换语言不触发读取或保存。

## 插件静态元数据

`@aura/plugin-sdk 2.5` 增加可选 manifest `localization`，供目录和 Schema 表单在页面 bundle 加载前使用。Site 与 Tripo 已提供完整六语言元数据。第三方插件需声明 `engines.pluginSdk: "^2.5.0"`，原有插件不必更改，原名称和说明继续兼容。

下面是 manifest 中的局部示例，其余贡献与权限字段保持原样：

```json
{
  "localization": {
    "catalogs": {
      "en": {
        "name": "Example tools",
        "report": "Create a report",
        "prompt": "Report content",
        "hint": "Describe the content you need",
        "short": "Concise",
        "full": "Complete"
      },
      "zh-CN": {
        "name": "示例工具",
        "report": "生成报告",
        "prompt": "报告内容",
        "hint": "描述需要的内容",
        "short": "简洁",
        "full": "完整"
      }
    },
    "nameKey": "name",
    "flows": {
      "report": {
        "titleKey": "report",
        "input": {
          "/properties/prompt": {
            "titleKey": "prompt",
            "placeholderKey": "hint"
          },
          "/properties/mode": { "enumKeys": ["short", "full"] }
        }
      }
    }
  }
}
```

`catalogs` 允许 `zh-CN`、`en`、`ja`、`ko`、`ru`、`fr`；英文及所有引用键必须存在，其他语言缺项回退英文。字符串按字面显示，`{{...}}` 不作为模板执行。插件可用 `@aura/plugin-sdk/metadata` 的类型和校验器检查声明。

插件可声明 `nameKey`、`descriptionKey`；`flows` 与 `actions` 使用本插件的局部贡献 ID，每项可声明 `titleKey`、`descriptionKey`、`input`、`output`。后两项按 JSON Pointer 映射到现有 Schema 节点，例如 `/properties/prompt`、`/items/properties/count`；`~1` 表示 `/`，`~0` 表示 `~`。节点支持标题、说明、placeholder 和按原枚举顺序排列的 `enumKeys`；多选枚举映射到字段的 `/items`。仅实际支持该控件的界面展示对应标签，未匹配的节点保持原值。

宿主只在显示层绑定键，不把翻译写入 Schema。表单值、枚举值、默认值、校验、Flow/Action 原标题和说明、模型提示词与提交内容保持不变。带绑定 Schema 的结构化结果可以翻译列名；旧运行的 Schema 和记录不会被当前插件定义替换，自定义会话标题与用户内容保留原文。

资源随 manifest 本地发布，插件管理器只读校验；停用插件仍能显示说明，不读取或执行其贡献代码。运行时只为公开目录附加资源，DSH 子进程环境、执行目录和持久化身份不含词库。前端为每个目录/设置读取方分配独立 namespace，刷新替换、卸载清理。修改 manifest 后按现有插件配置应用流程生效，不因界面语言变化重新读取或保存。

## 验证

运行时单测验证语言协商、存储失败、英文回退、复数、资源生命周期和格式化。目录审计检查六语言、各语言复数类别和插值一致性。workbench 的 `language-browser.test.ts` 在合成数据环境中切换六种语言，覆盖宽窄布局、未保存草稿、插件挂载次数、缓存状态与通知，并确认没有新增后端调用；需要 `CHROME_BIN` 指向 Chrome/Chromium/Edge。

`feature-language-browser.test.ts` 在 320px、360px 和宽屏下验证自动化与 MCP 表单草稿、已出现的校验/搜索错误、模型选择和用量显示，确认六语言切换不保存或重新发起请求。测试还以合成浏览器宿主和终端事件流验证页面地址草稿、ARIA 标签和连接生命周期：浏览器租约、终端实例与事件流只创建一次，卸载时释放，不因语言变化重新导航或发送终端输入；实际布局变化允许同步终端尺寸。命令目录单测同时验证本地化搜索、稳定命令标识和用户内容保留。

根测试 `i18n-catalogs.test.ts` 审计宿主和两个产品插件；`plugin-language-layout.test.ts` 以合成 Site 项目检查六语言和加长文本在 320px、360px 与宽屏间的布局、输入节点身份、数据不写入、订阅不重启。`productPlugins.test.ts` 通过真实 DSH 模块加载器检查两个构建后的插件在六语言下的显示与资源卸载。

静态 manifest 词库也纳入六语言目录审计。协议与插件管理器测试验证资源上限、引用、只读发现及停用插件；`host-health.test.ts` 验证真实 DSH 边界和大于 Windows 单个环境变量上限的词库。`metadata-browser.test.ts` 使用真实目录 hook、插件设置、Flow 卡片和表单，合成 HTTP 验证六语标题、提示、枚举与结果列、草稿/焦点保留、显式停用/刷新和资源清理；切换语言不新增请求或写入。

`model-checks-browser.test.ts` 通过真实模型设置组件与合成 HTTP，验证六语言下已出现的检查结果、HTTP 错误、旧响应回退、反馈样式、未提交草稿及焦点，检查次数只随显式操作增加。协议测试验证投影边界；运行时 `model-connection.test.ts` 经真实 DSH 调用本机合成模型，检查身份校验、空响应、固定探测提示词、次数与凭据隔离；不代表真实账号或付费模型已验证。

`conversation-language-browser.test.ts` 使用真实对话组件、会话存储和发布的 DSH 遮罩，HTTP 与事件流使用合成数据。六语言与三种宽度下检查草稿、答案选择、自定义回答、展开的工具组、遮罩显隐状态、轨迹缩放范围和保留的错误，确认语言变化不重连或新增请求；审批和问题提交仍携带原选项与用户文本。`subagent-panel.test.ts` 同时验证六语言切换保留选中项与缓存结果、不重启轮询，记录读取失败仍与执行失败分开。运行时单测另覆盖异步错误的嵌套消息引用。

新增页面还需检查实际渲染、窄屏长文本、键盘/无障碍标签与离线资源。伪本地化由 `pseudolocalize` 提供，供布局回归使用。

`workflow-language-browser.test.ts` 使用真实表单、工作流会话与结果组件和合成接口，在六语言、320px／360px／宽屏下验证草稿、枚举值、预览选择、步骤尝试、原始 JSON 和错误保留，并确认语言变化不发送命令或重启读取。未确认命令仅在用户再次提交时重发，仍使用同一个 request ID 和原始答案。工作流工具栏和运行模式选项在窄屏自动换行；截图检查使用仓库的系统字体栈。

该测试同时在固定尺寸 iframe 的准确窄／宽视口中验证产物弹窗的焦点、文件选择、下载地址和布局，以及图片缩放、加载失败和模型视角保留，并断言实际视口宽度。3D custom element 使用合成适配器验证组件生命周期，不代替真实 GPU／模型文件渲染测试；产品构建仍使用发布的查看器依赖。

`flow-editor.test.ts` 还验证六语言下的草稿、撤销、分析 ID、导入校验、分析错误、保存失败、菜单与 SVG 节点身份，确认切换语言不写草稿／分析缓存、不重新分析。画布布局在 320px、360px、中等和宽容器下检查；源码修改、旧回复拒绝、撤销与刷新恢复仍使用原有回归。

`peripheral-language-browser.test.ts` 在准确的 320px、360px 和宽视口中验证分隔条拖动／取消／提交、文字选区、工具条焦点与布局，以及已出现的插件错误。视口由固定尺寸 iframe 提供，避免操作系统的浏览器窗口最小宽度影响窄屏检查；合成指针事件与时钟驱动真实控件逻辑，布局仍由浏览器计算。`pluginBrowser.test.ts` 使用真实 DSH 发布包验证脚本加载失败的翻译标识、旧页面与样式保留、第三方错误原文及后续恢复。

`transport-language-browser.test.ts` 使用真实 hooks、会话存储与合成 HTTP/事件流，验证六语言下已出现的错误、缓存、工作区选择、草稿和未确认命令保留；切换语言不重建事件流、不保存历史或重复提交。显式重试工作流复用原请求 ID、模式和输入，目录的 ETag 与 304 行为保持不变。传输单测另验证 HTTP 状态、超时、取消、可读兼容错误和底层原因。

公开接口见 [i18n 包](../../packages/frontend/i18n/README.md)和[插件 UI SDK](../../packages/frontend/plugin-ui/README.md)。

`public-errors-browser.test.ts` 验证真实 Site/Tripo 组件、登录 hook 和浏览器面板保留 HTTP/原生错误、草稿与焦点，六语切换不重发操作、不写入项目或重启订阅；HTTP、登录弹窗和原生端口为合成实现。`public-errors.test.ts`、`native-errors.test.ts` 另验证取消信号、请求身份、原始路径、序列化、旧 Error.message 和未知码回退。

桌面启动与原生语言测试见 [desktop README](../../apps/desktop/README.md)。真实 Chromium 布局检查覆盖准确窄视口、六语言、加长文案、加载/失败状态和重新加载按钮焦点；原生 IPC 单测使用合成 Electron 端口，验证来源限制、卸载、原始文件路径与取消，不会打开实际选择框或访问用户数据。
