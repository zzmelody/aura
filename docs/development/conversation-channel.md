# 会话执行与可恢复连接

Agent 执行由 `@aura/agent-runtime` 持有。浏览器、Electron renderer 和 Capacitor 只提交命令、查询状态和订阅事件。关闭页面、取消 HTTP 请求、SSE 断开或切换客户端不会停止已经接收的执行。Runtime 整体退出仍会停止执行；本轮不包含远程中继和后台常驻。

## 执行与命令

`conversation-executions.ts` 拥有执行准入、取消、完成 Promise 和关闭清理。每个会话从准备到最终回执落盘只允许一项执行。模型执行期间仍可处理控制命令。执行超时、权限、付费预算和 DSH 的子 Agent 清理沿用原驱动。

| 标识          | 含义                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| `commandId`   | 客户端生成的 UUID，一次用户操作的去重键                                               |
| `executionId` | 一次启动命令的执行 ID，当前等于启动命令 ID；目标模式可含多个 DSH 回合                 |
| `turnId`      | `turn-<DSH turn/start seq>`，在同一会话内稳定；实时事件和历史使用相同投影             |
| `cursor`      | `<epoch UUID>:<sequence>`，事件传输位置，与历史分页的 `beforeSeq` / `throughSeq` 独立 |

`@aura/protocol/conversation-channel` 导出公共 DTO。HTTP 命令与事件协议版本为 1，命令在后端进行严格校验，不接受 provider、URL 或凭据。

| HTTP 接口                                      | 行为                                                          |
| ---------------------------------------------- | ------------------------------------------------------------- |
| `POST /coding/sessions/:id/commands`           | 接收命令；首次接收返回 202 和回执，重复查询式提交返回已有回执 |
| `GET /coding/sessions/:id/commands/:commandId` | 查询接收及处理结果；未找到返回 404                            |
| `GET /coding/sessions/:id/snapshot`            | 获取最近历史窗口、执行状态、协作状态、待回答问题和当前游标    |
| `GET /coding/sessions/:id/events?cursor=...`   | SSE；也接受 `Last-Event-ID`，请求头优先                       |

支持 `turn.start`、`turn.steer`、`turn.stop`、`question.answer`。启动参数位于 `input`；其余命令必须携带目标 `executionId`，回答另外携带 `questionId`。迟到的控制命令不能作用于后续执行。相同会话和命令 ID、相同规范化内容返回原回执；同一 ID 修改内容返回 409。

回执状态为 `accepted`、`applied`、`rejected`、`uncertain`。启动回执的 `applied` 表示已经进入执行调度，最终结果由 `execution.status` 表达。执行状态包括 `preparing`、`running`、`stopping`、`complete`、`stopped`、`error`、`interrupted`。问题等待期间执行保持活动，快照中的未回答问题用于展示等待状态。

新的 `aura_conversation_commands` storage domain 保存命令摘要、宿主世代、回执和执行关联。接收记录落盘后才调度操作，启动的调度标记在模型或工具副作用前保存。回执不自动删除，从而避免旧命令重新执行；不逐 token 持久化传输事件，也不改写旧会话 domain、ID 或 DSH JSONL。

进程重启后，旧世代的未确认命令投影为 `uncertain`，仍活动的执行投影为 `interrupted`；读取不会自动重新发起执行。已经发出的操作与回执写入不能组成跨服务事务，因此结果不确定时只保留证据并等待用户决定，不承诺外部副作用 exactly-once。现有付费预算预留规则继续适用。

## 快照与事件

`conversation-events.ts` 每个通道保留至多 256 条、256 KiB 的事件，至多缓存 64 个通道。淘汰通道会换世代，单次事件过大也会使旧游标失效。通知和提前出现的 Flow 卡片另外保留有界运行时投影，用于补充尚未出现在历史中的信息。DSH 历史始终是持久化正文的来源。

SSE 消息包括：

- `snapshot`：首次连接的快照及游标。
- `event`：带版本、会话、执行关联、可选回合 ID 和游标的事件；内容为执行变化、命令回执或活动。
- `reset`：游标过期、来自另一个通道或宿主世代改变时的新快照。
- `heartbeat`：空闲连接心跳。
- `unavailable`：当前订阅不可继续，客户端可以重连。

快照在事件修订未变化的区间读取历史；读取期间有新事件则重新捕获，连续变化时返回 503，由客户端稍后重连。快照捕获后发生的事件保留在重放窗口中，下一次读取从快照游标继续。若期间窗口再次淘汰，订阅重新发快照，不能跳过缺失事件。

HTTP 适配器以短 RPC 读取事件页并输出 SSE，不把 HTTP 取消传给执行。慢客户端最多影响自己的 reader，不阻塞 DSH。订阅取消会结束轮询和后续读取。历史中 `turnId` 是读取投影，旧日志无需迁移。

## 工作台

`ConversationStore` 按 Runtime endpoint 和会话共享一个读取器。视图卸载只解除订阅。首次连接和重置替换快照；增量事件触发合并的快照刷新，因此多端使用相同的历史投影。刷新失败保留上一次已知执行状态，连接状态单独显示。重连只发读取请求。

发送前将待确认命令保存在当前客户端本地存储，确认回执后移除；存储不可用时保留内存副本。这里保存用户提交的命令内容，不包含模型或 OAuth 凭据。响应丢失先查询原 ID；找不到确定结果时显示“查询并重试原命令”，只有用户点击才重新提交同一 ID，避免生成一个新的启动命令。

完成状态须等执行清理及最终回执处理结束才发布，客户端不能因流结束或 HTTP 超时自行标记任务成功、失败或停止。宿主重启后显示中断提示，用户可以检查历史后显式继续。

旧 `/coding/turn` 和 `/chat/*` 格式保留为同一执行服务的观察适配器。旧客户端没有稳定命令 ID，因此不能获得新命令接口的跨请求去重保证；其连接断开同样只解除观察。

## 验证

单元测试覆盖取消观察、并发准入、重复提交、目标执行绑定、重启投影、快照修订、窗口淘汰和收尾落盘时序。HTTP 集成测试使用真实 DSH 与本地合成模型，验证 SSE 断开后继续、按游标重放、旧流接口断开、显式停止、跨客户端回答及持久化回执恢复。工作台测试覆盖共享订阅、重连游标、状态保留、历史窗口合并、确定拒绝和未知结果的显式重试。所有测试使用隔离目录或内存存储，不需要付费凭据。
