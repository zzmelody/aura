## 复现与实施边界

原实现只为已 import 的模块记录元数据；未 import 的 JSON／YAML 资源收到原生通知就增加版本。Windows 仅访问时间变化、内容不变时也可触发通知，进而使后端被替换。隔离用例已复现该机制；尚未证明此前两次实际量化任务取消均由它造成。

实施前在根 `local/quant-source-watch-v2-20261109/registration.json` 登记源码与测试摘要。先增加行为回归，原实现为 3 项通过、2 项失败，分别复现只改访问时间导致版本变化，以及重复资源事件多次增加版本。此前仅忽略未 import 资源的隔离候选没有应用，因为它会丢失启动 JSON／YAML 及 package／manifest 的更新。

现在先注册原生监听，再一次性建立该根源码及 JSON／YAML 资源的字节基线。后续事件合并为路径，在下次刷新核对元数据与内容；相同字节不切换版本。保留真正修改、创建、删除、恢复、原子替换及同长度且恢复修改时间的编辑。非 import 的启动资源同样参与核对。

只读显式插件目录，跳过 node_modules、隐藏路径，不遍历资源目录符号链接或读取资源符号链接目标。摘要逐块计算、仅存内存，不作为执行指纹、兼容性授权、恢复判据或历史 sourceHash。没有修改已发布 DSH／pi-ai 依赖、用户配置、数据快照或研究记录。

写入未完成时恰好到来的刷新仍可能看见中间内容；原有加载失败保留上一版的行为继续有效。文件事件不构成可靠的跨文件构建事务，也没有改动插件自行拥有后台任务的生命周期协议。
